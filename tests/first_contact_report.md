# 首次接敌与实体材质修正

## 修正

- 大厅收到 catalog 后分批准备两种美术模型缓存（含天启升级形态）、建筑、弹道和挂件。
  每个资源任务间让出事件循环，重复目录不整批重建。
- 首次用户点击建立音频上下文后静默生成音效缓存；不播放声音、不创建声音实例。
  音频对象销毁后中止剩余预热。
- 预编译使用真实 HDR 场景缓冲区的输出格式，并覆盖闪光灯 0 / 1 / 2 盏的变体。
  编译提交后立即恢复渲染目标和灯可见性，再等待编译结束，不污染实战画面。
  保留闲置时关闭闪光灯的逻辑，不增加日常动态光源数量。
- 主体材质明确使用不透明、深度测试和深度写入；施工保留升起/进度条，取消整体透明闪烁。
  放置预览、粒子等独立提示材质不变。降低实体轮廓补光和桥梁样板环境反光。

## 实测（本机浏览器，离线真实渲染器）

铁峡争渡、全部阴影、轻量泛光，固定样板镜头，暂停场景后触发首次爆炸。
每组为一次测试；CPU 指标只计 renderer.render，非完整游戏/网络/音频耗时。
第一帧 interval=0 是恢复暂停的时间戳重置，不是实际帧耗时。

| 场景 | 首帧 CPU ms | 后两帧 CPU ms | 着色器程序数 前 → 后 |
| --- | ---: | --- | --- |
| 180 次爆炸，未预热 | 167.4 | 15.4 / 2.2 | 42 → 72 |
| 180 次爆炸，已预热 | 36.7 | 2.5 / 3.4 | 160 → 160 |
| 单次爆炸，已预热，施工建筑 | 21.0 | 2.2 / 2.3 | 160 → 160 |

预热计数 90 个单位/建筑版本，实际 WebGL 无捕获的 error/warn。
修正消除了该测试中首次闪光导致的新增着色器编译，仍有首次 GPU 缓冲上传、
特效处理等开销；不声称所有硬件首帧都小于 16.7 ms，也不保证抢在预热完成前开战不会卡。
代价是提前保留有界的模型缓存和光照程序变体，非零内存成本。

施工状态截图复查：主体保持实体遮挡；接地标识、窗口和独立粒子不是实体蒙皮的一部分。
专项测试覆盖任务让步/去重、音频缓存/取消、三种灯数预编译及状态恢复、不透明深度设置。
