# 2026-09-08 渲染升级实测

本轮是保留程序化低面数模型和实例合批的写实化升级，不是替换成全套 AAA 扫描资产。
未改变单位属性、地图碰撞、射程和网络协议。工作区原有 H 停止/采矿逻辑改动保留。

## 画面改动

- 步兵收腰胸腹、分离肩甲、屈膝、双手托枪；履带改成中空圆端结构和可见负重轮。
- 全部 30 个单位/形态的近景、15 类建筑主体首次生成时缓存顶点遮蔽；远景和局部轴挂件不烘焙。
- 所有单位/建筑的金属、涂装、织物、石材、晶体使用逐光源高光，遵循阴影与大气雾。
- 修正纹理的线性/感知亮度阈值，局部坐标固定纹理，远景逐渐减弱微凹凸。
- 默认建筑阴影档补上单位接地影；单位近景接收太阳阴影。太阳/补光方向不受地图位置与阴影开关干扰。
- 关闭泛光仍保留自然调色和 FXAA（2 个全屏 pass）；轻量 5、完整 7。避免关闭泛光就同时失去抗锯齿。
- 普通单位 900 距离进入低模，巨龙/高阶天启延后到 1350，附属动画与对应 LOD 同步。

## 性能条件及原始结果

浏览器：Codex 内置 Chromium / WebGL2，ANGLE Direct3D11，Intel Arc Graphics（0x00007D55）。
视口 1920×1080，铁峡争渡，固定地图种子 90241；400 移动单位 + 15 建筑，镜头
`x=1000,y=1500,zoom=0.82,yaw=0.14,pitch=0.96`。
画质：建筑阴影、关闭泛光、自动 LOD、粒子上限 150、探索图缩放 9。
每轮预热 90 帧，采样 300 帧。基线来自 Git HEAD ee901f7 的渲染模块。

| 版本 / 内部分辨率 | 平均 FPS | 帧间隔 p50 / p95（ms） | CPU render p50 / p95（ms） |
| --- | ---: | --- | --- |
| 旧版 / 1920×1080 | 60.00 | 16.7 / 16.8 | 1.6 / 2.2 |
| 新版第一次 / 1920×1080 | 51.87 | 16.7 / 41.7 | 1.6 / 2.2 |
| 新版第二次 / 1920×1080 | 60.00 | 16.7 / 16.8 | 1.7 / 2.3 |
| 新版第三次 / 1920×1080 | 55.80 | 16.7 / 24.9 | 1.6 / 2.1 |
| 新版 / 1728×972（90%） | 60.00 | 16.7 / 16.8 | 1.8 / 2.4 |

最后一轮仍然是 400 精细模型、0 远景模型。场景绘制调用 134→135，三角形
616005→659645（约 +7.1%，统计包含阴影等场景绘制，不含后处理）；新增接地影占一个实例批次。

不能把单次 60 FPS 当成任何硬件下不掉帧的保证；原生分辨率仍有抖动，原因未通过 GPU 时间查询完全归因。
夹具不含真实联网/游戏 UI/寻路、没有执行完整自动调节状态机；90% 是手动固定到现有自动保帧首档的测试。
现有游戏自动逻辑在低于 56 FPS 持续约 0.6 秒后降一个分辨率档（严重掉帧更快），
稳定接近 60 FPS 约 12 秒再恢复；开始后约 2 秒预热，不在后台调整。

## 动态切档及资源

- 同一个 renderer、同一场景，关闭阴影开局后即时打开，森林/山石/桥梁投影恢复，不重建地图。
- 30 单位在 zoom=0.5 时为 3 精模 + 27 远景；禁用 LOD 后即为 30 + 0，重新自动后恢复 3 + 27。
  这是开发夹具对已有渲染 API 的验证，正式设置面板目前没有模型高/中/低下拉框。
- 正式设置需要点击“保存”应用；模型选择在下一渲染帧更新。FPS 提示增加精模/远景数量。
- 三张地图连续切换 4 轮（12 次），同图 GPU 资源数量稳定：五车争霸 107 个 geometry，
  赤金陨坑 108，铁峡争渡 116；纹理都是 12，共享纹理 4；同图 fog shader 分别 5/8/13，water 0/0/2。
  已修复地图/矿簇资源和失效 shader 引用泄漏，存活的共享贴图、单位缓存和建筑地垫保留。
- 浏览器检查了三档阴影、三档泛光和两种 LOD 状态，没有 WebGL shader 编译错误。
