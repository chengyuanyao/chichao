# 战报明细 v3 验收（2026-09-17）

## 范围

- 新增“交战与贡献明细”栏目，按玩家折叠，默认展开自己。
- 分兵种 / 建筑 / 其他火力来源：对兵伤害、对建筑伤害、有效承伤、生产完成原价、首次 / 末次完成时间、终局存量及原价。
- 玩家交战表：互相伤害、击毁单位 / 建筑、其中矿车、击毁价值、被该玩家击毁价值、交换比。
- 战损来源拆为敌方击毁、主动自爆、中立 / 友伤 / 环境等；被毁矿车的未卸载携矿损失单列。
- 建筑建成数量和初始数量补入原有兵种与运营表；CSV 同步上述明细。
- v1 / v2 历史档案继续按原有数据展示，不伪造新字段。

## 统计口径

有效伤害为伤害结算后的实际扣血，上限为本次命中前剩余生命；不统计中立、友伤、自己或退场后的交战。维修回血后的再次受伤可累加。敌我关系取命中时的关系，不能用终局队伍倒推。

最后一击与伤害贡献分别统计，发射单位死亡后仍使用弹丸保留的来源兵种。产出按目录原价，不是现金支出；初始、赠送、未完工、撤单、基地展开不重复计生产。终局存量由终局实体扫描统计，不用“生产减损失”推算，以避免出售、转换和撤离造成虚假存量。携矿损失不并入单位目录价战损。

## 验证

- 11 个 Python 测试脚本通过：damage、suicide、combat_reward、building_death_combat、headquarters_build、team、alliance、veteran_regen、battle_report_details、battle_report_operations、battle_report。
- 全部 20 个 `tests/*test.mjs` 通过，包含旧版兼容、5 个页签、HTML 转义、CSV 公式防护、空数据和本地历史保存。
- 战报 HTTP 回归覆盖鉴权、整局结束前不可读取、换局隔离与终局冻结。
- 新增回归覆盖有效伤害 / 溢出 / 重复死亡 / 来源 / 交战双方对应 / 携矿 / 三类战损 / 建造去重 / 转换 / 存量 / 淘汰 / 冻结。
- 连续 10,000 次命中只累计有限的玩家、目录兵种键，不逐次追加事件。

## 性能

无新增客户端游戏帧渲染工作；明细仅终局读取、展示。服务器在现有伤害 / 出厂 / 完工 / 死亡钩子中累加，只有终局额外扫描一次存活实体。不保存逐击日志，不扩展实时房间快照。

本机 Python 3.13，基线 `c64db8d` 的战报模块与当前模块，在同一份服务器中依次 A/B/B/A 运行现有 `performance_test.py`（4 玩家、404 单位、120 tick）：

| 版本 | 平均 tick ms | p95 ms | 最大 ms |
| --- | ---: | ---: | ---: |
| 基线 A1 | 3.71 | 7.81 | 13.93 |
| 当前 B1 | 3.74 | 7.23 | 12.93 |
| 当前 B2 | 3.55 | 6.81 | 11.80 |
| 基线 A2 | 3.69 | 7.50 | 11.50 |

所有轮次通过现有预算门槛，未发现稳定的模拟耗时回退。独立伤害统计钩子每组 100,000 次、重复 5 组的中位耗时从 0.542 µs/次变为 0.928 µs/次，说明新统计不是零成本，但每次增量约 0.386 µs。该结果是服务器测试，不应宣称为全硬件实机 FPS 保证；本轮未做浏览器视觉截图验收。
