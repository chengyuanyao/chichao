# 赤潮：钢铁前线

一个原创的浏览器局域网 3D 即时战略游戏，玩法参考经典基地建设 RTS，但不使用《红色警戒 2》的代码或美术资源。

## 立即开战

启动服务器后，窗口里会打印这台电脑的局域网地址，形如：

**http://192.168.1.20:18081**

同一局域网内的玩家用 Chrome 或 Edge 打开那个地址，输入代号后即可建房或输入 6 位房间码加入。
地址由服务器自动探测，换网络或换机器都不用改代码。

如果服务器没有运行：

- **Windows 图形启动器：** 双击 `SteelFrontLauncher.exe`，点击“启动服务器”；同一个按键可停止服务，全程不显示控制台窗口。停止或关闭 EXE 会结束服务器及其派生的 AI 副官进程树，并确认监听端口已经释放。
- **Windows：** 双击 `start-game.bat`
- **Linux / macOS：** 在项目目录执行 `./start-game.sh`（或 `bash start-game.sh`）

`SteelFrontLauncher.exe` 是一个很薄的启动外壳，不把游戏代码打包进去。它每次都直接
运行仓库当前的 `server.py`，因此执行 `git pull` 后无需重新编译，下一次点击启动就是
最新代码。Python 3 仍需安装在电脑上；启动错误会写入根目录的 `launcher.log`。
房间没有任何浏览器玩家在线后会保留 10 秒重连窗口，随后自动从房间列表移除；正常刷新页面不会误删房间。
只有修改了启动器自身的 `launcher/SteelFrontLauncher.cs` 时，开发者才需要运行
`powershell -ExecutionPolicy Bypass -File launcher/build-launcher.ps1` 重新生成 EXE。

启动后窗口里会直接打印两个地址：本机访问用的 `127.0.0.1`，以及**自动探测到的局域网地址**——把后者发给队友。保持该窗口开启；关闭窗口即停止服务。

- 换端口：`start-game.bat 8090` / `./start-game.sh 8090`，或设环境变量 `PORT`。
- Windows 下如果启动失败，窗口会保留错误信息；按任意键后再关闭，便于排查。

### 端口说明

默认端口是 **18081**，不是常见的 8080。原因是：装了 WSL2 / Hyper-V / Docker 的
Windows 机器会在开机时预留大段动态 TCP 端口，8080 常常落在里面，绑定时会报
`WinError 10013`（“以一种访问权限不允许的方式做了一个访问套接字的尝试”）。
这**不是**端口被别的程序占用（那是 10048），换端口即可。

想确认某个端口是否被系统预留（普通 cmd）：

```
netsh int ipv4 show excludedportrange protocol=tcp
```

服务器遇到绑定失败时会直接把上面这些排查步骤打在窗口里，不会只丢一段 traceback。

浏览器需要支持 WebGL2（Chrome / Edge 近几年的版本都可以）。three.js 已内置在 `public/vendor/`，客户端不需要联网。

## 玩法

- 房间支持 2–5 名玩家，可由房主加入 AI，共 3 张地图。
- 两位阵营：**钢铁军团**（科技）与 **秘法会**（魔法）。房主可在大厅为每位玩家选阵营。
- 房主可为玩家分配队伍与出生点，同队玩家共享视野且无法互相攻击。
- 房主可在开战前选择是否开启“战斗奖励”；默认关闭，开启后击毁敌方单位返还
  其造价的 8%，击毁建筑返还 5%，友军、自毁和中立目标不产生奖励。
- 大厅 **动态结盟** 默认开启：对局中可向其他人发起提议，对方接受即并入同一队伍，也可
  随时退盟。房主关闭后，大厅预先分好的盟友仍然有效，但整局禁止结盟、接受和退盟，
  开局队伍保持锁定。
- 钢铁军团从指挥中心、磁能电站、矿石精炼厂、采矿车和初始守军开局；秘法会对应魔法主堡、法力塔、水晶精炼所与浮游晶簇。
- 自爆卡车与爆裂魔仆的爆炸对建筑、采矿车和浮游晶簇为 ×1.5，对其余单位（含天启坦克、秘法巨龙等高血单位）统一为 ×0.8。
- 钢铁军团建造步兵营、重装工厂、战地维修厂和炮塔，训练突击兵、火箭兵、狙击手、军犬、磁暴兵，以及先锋坦克、猎犬战车、攻城炮、坦克歼击车、天启坦克、光棱坦克、自爆卡车、基地车等。
- 秘法会建造奥术圣殿、召唤法阵、圣泉和奥术塔，训练晶刺、奥术法师、冰霜女巫、虹视使，召唤岩石傀儡、影豹、爆裂魔仆；圣泉解锁秘法巨龙、晶铠卫士、裂地晶兽与坠星台。迁徙法阵可展开为新的魔法主堡。
- 兵种相克：军犬克步兵与法师（一口咬死步兵与虹视使；晶刺/法师/女巫/魔仆一口剩血、两口仍死），狙击手克单个步兵，攻城炮克建筑，火箭兵与坦克歼击车克重甲，奥术法师熔重甲，磁暴/狙击克魔导甲（×1.6）。自爆卡车与爆裂魔仆靠死亡/贴脸爆炸清步兵堆和成团建筑，对天启坦克、秘法巨龙这类高血单位只有 ×0.8，打散开的高血载具更差，单车拆不掉满血总部。
- 基地车（或迁徙法阵）可在合适地形展开成新总部，也能重新收起转移。
- 钢铁军团的战地维修厂可持续消耗资金修复坦克、战车与采矿车；秘法会的圣泉用同一套流程修复傀儡、巨龙与晶簇。电力/法力不足时维修速度会下降。
- 战场采用红警 2 式探索黑幕：未探索区域为黑色，单位探开后地形永久显示；
  敌方移动单位仍需处于当前视野内才会出现。各兵种保留原本的基础视野；远程武器若
  射程更远，视野自动扩到射程的 110%，确保看得到攻击目标且不会压窄近战侦察视野。
- 地形以**山脉与山谷**分区：山地完全不可通行也不可建造，道路行军速度 +35%。
  赤金陨坑·紧凑的外环邻里通道用密林 + 林间小路卡口；狭路对峙以山谷作为要道。
- 部队会自动用 A\* 绕行；道路的寻路代价更低，所以大规模调动会自发沿公路走。
- 当前保留 3 张地图：五车争霸 4000×4000（5 人，中央折叠基地车开局）、
  赤金陨坑·紧凑 6400×6400（5 人，中庭金库）与狭路对峙 4800×3200（2 人）。
  赤金陨坑·紧凑使用五条林间卡口；狭路对峙保留三条可绕行山谷。
- 五车争霸为 4000×4000 的五人折叠开局图：五辆基地车集中停在中央，玩家先抢方向
  再展开；外围五个 72° 方向各生成一片随机位置的 23 万矿，中央固定矿储量 46 万，稳定为
  外围单片矿的两倍。整张图不生成中立矿区守军。
- 建筑先进入生产倒计时，完成后才能在基地控制区内部署。
- 只有已完成的核心基地建筑能逐步扩张控制区，炮塔不能延伸建造范围。
- 采矿车会自动采矿并实际驶回精炼厂卸矿，不再满载后瞬移；各家拥有固定保底矿区，
  其余公共矿区每局随机生成，并保证避开出生区、阻挡地形且可达。大厅 **中立守卫**
  （默认开）开启时，公共矿由中立炮塔与守军占据，全部清除前采矿车不会开采；机动
  守军被引离矿区过远会脱战并返回哨位。关闭后矿点仍在且可直接采集，不再刷中立单位。
- 摧毁敌人的总部（指挥中心或魔法主堡）即可淘汰对方，坚持到最后者获胜。
- 队伍模式下，任一队友的总部被摧毁不会导致全队淘汰，消灭敌方全队即可获胜。
- 补给箱可能掉落资金、医疗或超级武器充能。玩家超级武器是手动瞄准的**轨道打击**（散布半径 180 / 溅射 60）。大厅可选 **轨道天降**（默认关）：开启后系统每隔约 40–60 秒在随机可通行地点落下范围×5 的轨道打击（散布 900 / 溅射 300），不消耗玩家充能，也不放大手动超武。大厅可选 **中立守卫**（默认开）控制公共矿区是否刷中立守军。大厅可选 **指挥官模式**（默认关）：适合手机。人类只下方针（速推 / 发育 / 防守 / 偷家）并在小地图点主攻或防守点；**方针一变立即清掉该席位的作战微操**（矿车和基地车继续干活），由内置大师 AI 或已绑定的外部副官执行。关闭时对局与现在完全一致。

## 操作

- 左键：选择单位、建筑或当前视野内的矿脉；拖拽可框选多个单位。Shift / Ctrl 可加选。
- 选中矿脉会显示剩余储量、总储量和百分比；战场矿簇与小地图按贫矿（＜0.8万）、
  普通矿（0.8–3万）、富矿（3–8万）、巨矿（≥8万）使用不同规模图例，并随开采降档。
- 双击己方单位：选中当前能看见的同兵种；Shift+双击把该兵种加进现有选择。不会隔着黑幕全图点选。
- **右键生产卡片：取消该项生产并全额退款**（建筑撤建造队列，单位从队列末尾撤一个）。
- 右键地面：强制移动（抵达前不会被自动攻击打断）；右键敌军：攻击。选中己方炮塔后右键射程内敌军，可令炮塔优先攻击指定目标。
- 右键己方单位：改选该单位，不会改写其他部队已经在执行的移动。
- 选中受损载具/构装后右键己方维修厂或圣泉，或按 R 自动前往最近的维修建筑；移动、攻击、停止命令都能立即取消维修任务。
- 鼠标滚轮：缩放；WASD / 方向键：平移视角（方向跟随当前朝向）。
- `[` / `]`：旋转视角，PageUp / PageDown：调整俯角。
- Q：攻击移动（选中部队时），R：维修载具/修复构装，点按 S：停止（按住 S 仍可向下平移），G：地图信标。
- Ctrl+1 / Ctrl+2 / Ctrl+3：把当前选择存成编队；按 1 / 2 / 3 选中该编队；连按（约 350ms 内）跳转镜头。阵亡单位会从编队里丢掉。
- 生产部队：使用右侧生产卡片，不设置生产快捷键，避免与作战和镜头按键冲突。
- 空格：返回己方基地，Enter：战斗聊天。
- **指挥官模式**（大厅开启后）：点 速推 / 发育 / 防守 / 偷家 下达方针，点小地图设焦点。不需要框选或键盘热键。席位上的副官令牌可复制给外部执行器；副官用 `/api/join` 的 `role=agent` 与令牌接入，只能下部队/建造/训练指令，不能改方针。副官断开后内置 AI 按当前方针接回。

## AI 玩法

游戏里有两条互不相干的 AI 路线，解决的是两件事。

| | 换掉房间里的「添加 AI」 | 给人类玩家配副官 |
|---|---|---|
| 代码在哪 | 本仓库 `ai_commander/` | 独立项目 `rts-agent`，**不在本仓库内** |
| 跑在哪 | 服务器进程内 | 玩家自己的机器上，通过 HTTP 接入 |
| 怎么接入 | 启动时替换 `server.tick_bots` | `/api/attach` 换取已有玩家的会话 |
| 要不要 LLM | 可选，没有就按固定模板打 | 见该项目自己的说明 |

### 内置 AI 指挥官（`ai_commander/`）

会看克制关系的 AI，替换掉内置那套。用 `ai_commander/start.py` 代替 `server.py`
启动即可，房间里照常「添加 AI」，加进来的就是新 AI：

```bash
python ai_commander/start.py            # 启动时问一次 LLM API Key，回车＝不用
python ai_commander/start.py --no-llm   # 不问，直接固定模板
./ai_commander/start-ai.sh 18081        # Linux / macOS
ai_commander\start-ai.bat 18081         # Windows
```

配了本地或远端 LLM 就让 LLM 定出兵策略，没配就按 `ai_commander/templates.py`
里那张手写的「局势 → 配比」表打——**没有 API Key 也是完整可玩的**，不是降级演示。
无论策略来自哪一边，落地前都会过一遍克制安全过滤和经济硬约束。细节见
`ai_commander/README.md`。想跑回原版直接 `python server.py`，什么都不用还原。

### 连接 AI 副官（外部 agent）

战斗顶部的「AI 副官」会打开左下角私有对话窗口；玩家输入、LLM 回答、战场告警和执行
回执只对本人可见，不会混进多人聊天。支持两种接法：

- **本机 LLM / 自带副官**：点击战斗顶部「AI 副官」→「连接本地副官」生成 8 位配对码；在玩家
  电脑上的 `rts-agent/play.bat` 选择模式 3，输入房间号和配对码。模型地址与 API Key
  留在玩家电脑上，游戏服务器不会读取。
- **服务器 LLM / 公共副官**：管理员在服务器的 `rts-agent/.env.local` 配好 LLM，玩家打开
  副官窗口后点击「启动服务器副官」即可。服务器为每名玩家启动隔离的 headless agent 进程，
  对话历史、视野和控制会话互不共享。副官窗口标题栏的「停止副官」随时可以收掉它，
  离开本局和分出胜负时服务器也会自动收（headless 副官自己不会退出）。

服务器模式会自动探测相邻的 `CC/rts-agent` 或 `rts-agent` 目录；其它部署布局可在启动游戏
服务器前设置：

```bash
export RTS_AGENT_DIR=/opt/rts-agent
export RTS_AGENT_PYTHON=/opt/rts-agent/.venv/bin/python
export RTS_AGENT_MAX_PROCESSES=12
python3 server.py
```

`rts-agent` 的 `LLM_BASE_URL` 既可以填服务器本机的 Ollama/vLLM 兼容地址，也可以填远端
OpenAI 兼容服务。未配置 LLM 时，规则执行器仍可自动生产、巡逻和作战，但自然语言对话
会在副官窗口明确显示为不可用。

## 技术说明

- 服务端：Python 3 标准库，权威状态与 20Hz 模拟，零第三方依赖。
- 客户端：three.js（内置于 `public/vendor/`）+ WebGL2。地形、单位、建筑、弹道、爆炸的网格由代码生成；表面共用 4 张压缩 WebP 写实材质（军械、地表、森林、矿石）。
  - `public/render3d.js` —— 渲染层：场景、相机、三点布光与阴影、山地地形、迷雾、拾取。
  - `public/postfx.js` —— 后处理：亮度提取 → 两级模糊 → 合成（辉光 + AgX/ACES 电影
    色调映射 + 饱和度/对比分级 + 暗角）→ FXAA 抗锯齿。合成 pass 手动做 sRGB 编码并把
    感知亮度写进 alpha 供 FXAA 找边 —— 场景一旦先渲染进 FBO，画布的 MSAA 就失效了，
    FXAA 是辉光路径下唯一的抗锯齿。
  - `public/app.js` —— 网络、输入、UI、小地图；战场绘制全部委托给渲染层。
    命令卡与选中面板的兵种肖像由 2D canvas 程序化手绘（18 种剪影，缓存复用）。
  - 血条等 HUD 走独立的 2D 叠加画布（`#hudCanvas`），文字更锐利也更省。
- 画面基调参考红警3：**明亮饱和的白昼战场 × 厚重深色的苏军金属 HUD**。
  战场是高对比暖阳 + 冷色天光 + 亮色大气雾；HUD 是军橄榄炮铜面板、铆钉、黄铜描边、
  深红内衬与琥珀 LCD 数字（`styles.css` 的「苏维埃钢铁 v3」皮肤）。
- 山脉不是装饰背景，而是地图拓扑：连续山墙切出宽山谷，公路沿谷底穿过；玩家能从
  地形轮廓直接判断主路、侧翼和伏击口，不需要猜哪一块桥面能不能走。
- 天空带太阳盘与 FBM 流云；地面同步滚动**云影**（迷雾遮罩注入顺带乘一层噪声）——
  俯视角看不到天上的云，但地上滑过的暗斑会让人「知道」天上有云。
- 单位与建筑共用一张 1024×512 的压缩材质图集：左半是旧化军用钢板，右半是风化玄武岩；
  同一套片元着色器从真实纹理亮度提取微法线与粗糙度，以一次采样表达划痕、污渍和石面孔隙，
  不增加材质批次或绘制调用。两大阵营目录中的全部单位和建筑都走同一套近景写实规范：
  钢铁军团的装甲、车舱和建筑梁柱使用 8 边低面数倒角，步兵军服使用高粗糙织物表面；
  秘法会的长袍、岩躯、兽身与浮空底盘使用连续剖面体、椭球和圆肢体，硬质盾牌与晶炮才保留
  清晰棱线。发光灯条仍用最便宜的方盒，所有零件最终继续合并进原有实例批次；
  900 世界单位外仍切回 12 三角面的极简 LOD，避免为屏幕上几像素的单位浪费性能。
- 爆炸分五层：噪声撕裂的 HDR 火球 + 溅射火花 + 烟柱 + 地面冲击环/焦痕 + **点光源
  闪光池**（4 盏轮换，爆炸真的会照亮附近的单位和地面）。
- 美术风格：每个零件可以带**固有色**或**团队色**，由顶点属性 `aTeam` 区分。
  履带是橡胶黑、炮管是枪铁灰、地基是混凝土、精炼塔是锈色、线圈是铜色，
  团队色只留给装甲板与灯带 —— 否则一整座基地只是团队色的深浅变化，非常单调。
  自发光件用「顶点色分量 > 1」标记，着色器据此跳过光照，再被后处理提取成光晕。
  这三件事（固有色 / 团队色 / 自发光）用同一个材质表达，所以一座建筑只占
  **一次绘制调用**，一个兵种也只占一次。
  指挥中心的雷达、精炼厂的转筒、电站的线圈会持续旋转，基地静止时也是「活」的。
- 特效：爆炸由火球 + 火花 + 烟柱 + 冲击波环 + 地面焦痕分层叠出；烟走普通混合而非加色，
  否则深色在加色模式下等于不可见。残血建筑会持续冒烟，下达指令时目标点会打出扩散环。
- 地形网格密度按面积自适应（最细 26 世界单位一格，面片总数封顶 5 万）；大战场也受
  面片预算约束，不会按面积无限增加地形几何量。
- 山体不是光滑土包：穹丘上乘一层随绕山角度变化的**脊线噪声**形成放射状山脊，
  再叠高频岩面细节；岩块按相对高度分三段配色（山脚褐岩 / 中段灰岩 / 近峰压白），
  山脚另铺一圈碎石带。两层噪声都随高度衰减，山脚仍平滑收敛到 0，不会破坏
  服务端按半径判定的碰撞边界。
- 山谷宽度按军团通行设计，并由自动洪水测试验证所有出生点、公共矿和谷口互相连通；
  道路取样也会逐段确认没有画进山体。
- HUD：单位与建筑血条默认常显，带队伍色侧标和分段刻线；只有镜头拉到很远时才退回
  「仅受损或选中才显示」，免得整屏都是小色条。侧栏中段是实时战场态势读数
  （部队 / 建筑 / 采矿车 / 累计采集 / 击毁 / 损失 + 电力负载条，超载会闪红）。
- 山地会抬高地形并铺上程序化岩体。道路只保留行军加成与寻路代价，不再铺
  条带网格或路肩脏土。单位、建筑、选中环、地面贴花全部按
  `groundHeight()` 落到地表，不会浮在起伏之上。
- 全地图按主题生成仅用于表现的自然地表：草原是低缓草坡、草簇和稀疏碎石，荒地
  偏岩屑与枯草，城市降低起伏，陨坑加强碎石。出生区、矿区、道路和林道周围留白；
  小草与散石不进入寻路或建造碰撞，并合并为整张地图一个静态 Mesh。道路仍不绘制。
- 赤金陨坑·紧凑的林带只能从卡口通过；狭路对峙的限制区由连续山脊表达。
- 地表分层着色：山体转灰岩，其余按低频噪声在草绿与干土之间过渡。
- 地图黑幕从「一张贴在低空的平面」改成注入各地形材质的着色器遮罩 —— 平面盖不住比它高的
  山体，会出现黑暗中浮着几块岩石的穿帮。探索记录只增不减，单位离开后不会重新压暗地形。
- 同步：Server-Sent Events 实时快照 + HTTP 指令。
  - 每条 SSE 流的**首帧**携带地图、地形、矿脉布局和视距表；之后每帧只发变化的部分，客户端用缓存补齐。重连会重新收到完整首帧。
  - 探索黑幕由客户端依据视距表自行推导，服务端继续按当前视野过滤敌方实体，且不再逐帧
    重复下发一份友军位置列表。
- 性能：
  - 服务端用空间网格处理邻近目标、范围伤害、单位分离与可见性判定。
  - 客户端按兵种用 `InstancedMesh` 合批；发光件靠「顶点色 > 1 即自发光」并进主网格，
    单位与建筑各省一次绘制调用。
  - 山体岩块按山合并（原先一块石头一个 Mesh，12 座山就是 250 多个对象）。
  - 几何合并不做 `geometry.clone()`，直接把源顶点按矩阵变换写进输出缓冲。
  - 单位实例缓存上一帧的槽位、位置、朝向与队伍色；静止单位不再采样地表、重复合成
    矩阵或上传动态 buffer。GPU 血条只显示受伤/选中/生产状态并以 20Hz 更新，2D HUD
    也降到 20Hz；探索黑幕和实体增删整理只随 8Hz 服务端快照更新。
  - 服务端追击移动目标会复用直线路径，小幅目标漂移不再每 tick 重做地形射线；山地
    宽相位按网格缓存，单位分离只在靠近障碍时进入精确碰撞。432 单位混战本机实测由
    分离以 10Hz 做视觉松弛，集中索敌按 tick 分摊。432 单位混战实测平均约
    5.1–5.4ms/tick、P95 约 9.5ms、最坏约 20–21ms，不再出现首帧 60ms 索敌尖峰。
  - 同一模拟帧的单位公开数据只转换一次，同队玩家共享视野过滤结果，避免多条 SSE
    连接在全局锁内重复 round 坐标和创建数百个字典。
  - 地形建成后保存高度场；单位、建筑、血条和贴花用 O(1) 双线性采样落地，不再逐帧
    遍历全部地形阻挡物。四角反投影得到真实地面视口，离屏单位不做插值、落地采样或
    GPU 提交；静止镜头也不再重复更新相机、灯光、阴影投影与四次反投影。
  - 低于 56FPS 时在约 0.6 秒内把内部渲染分辨率逐级降至 90% / 80% / 70% / 60%，
    恢复稳定后缓慢升回 100%；
    这不会替换模型，所以兵种不会因为单位数量多而变成小盒子。
  - 只有镜头拉远时才切换低模；低模按兵种保留炮管、矿斗、导弹等特征，不再因单位
    数量达到阈值而把全场硬切成同一种盒子。
  - 晶铠卫士采用天启级视觉体量的巨型持盾构装模型；近景与远景共用宽肩、塔盾、晶锤
    剪影，几何仍按兵种合批，不额外增加绘制调用。
  - 天启坦克按战功变形，三副形态和换弹本身只改表现层；伤害、射速仍只沿用全兵种
    共用的军衔加成，换装不会在军衔加成之外再叠一层数值：
    出厂是冷钨钢涂装的双联重坦，按变形金刚的语汇分层——斜面主装甲外挂窄边框条、
    关节露出液压杆与轴销，车体上折着肩甲、膝甲和夹在双炮之间的头部模块；打满
    3 杀（一星）换暗铁 + 猩红 + 等离子回路的老兵涂装，弹道同步换成青白等离子
    穿甲弹；打满 8 杀（二星，含 16 杀王牌）直接展开成人形态，改用双臂炮射击，
    开火时抬臂、后坐，随后缓缓垂下。三副形态各是一份合并几何体 + 一个实例池，
    手臂另开一层实例（两条手臂合进同一份几何体，原点即肩轴），单位再多也不会
    退化成逐单位绘制调用；远景低模同样分形态，拉远不会变回原样。
  - 合并几何体额外携带两条顶点通道：`aOcc` 是建几何体时烘焙一次的环境光遮蔽，把
    缝隙、翼根、腹部和贴地处压暗，运行时零开销、不占贴图；`aSurf` 是逐零件表面
    通道，让金属、石面、布料、兽皮、晶体五种高光模型出现在同一次绘制调用里。
    两者都不拆合批。烘焙目前只对秘法巨龙开启（`OCCLUSION_BAKED_KINDS`），其余
    兵种拿到的是默认值，表现与开启前一致。
  - 遮蔽烘焙先做零件级配对剪枝，再逐顶点求和：每个零件按自身等效半径反解影响
    距离，远处零件整片跳过。巨龙首次出场的烘焙从 25ms 降到 9ms，明度误差 < 2%。
  - 秘法巨龙走「玉剑传说」玉龙路线：墨玉背 / 翡翠身 / 白玉腹三段明度，分叉金鹿角、
    后掠长龙须、颈后火焰形鬃鳍与背脊玉鳍，双翼是金梁配从深玉过渡到白玉的半透玉膜。
    玉件走晶体表面通道、金件走金属通道，和鳞身的兽皮通道同处一次绘制调用。近景、
    远景低模与建造面板的 2D 图标同步换色；翼展和包围球刻意保持不变，俯视点选半径
    继续有效。攻击特效同步换成玉息：弹丸白玉核 + 翡翠焰身、拖尾与命中爆点玉色、
    地面留痕从焦黑改成冷玉residue，并给龙口喷吐补了专属特效（过去落在通用暖白
    分支上）。粒子数量、爆点大小与存续时间一律不变，只换色相。
- 指令：普通移动严格服从玩家操作；需要沿途交战时使用 Q“攻击移动”。
- 默认监听：0.0.0.0:18081（可用 `PORT` / `HOST` 环境变量覆盖，或 `start-game.bat <端口>` / `./start-game.sh <端口>`）。

## 测试

```
python3 run_tests.py                  # 全部离线测试（跳过需已启动服务器的 integration）
python3 tests/<name>_test.py          # 单个纯逻辑测试
python3 tests/integration_test.py http://127.0.0.1:18081  # 需要服务器已启动
```

`multiroom_test.py` 锁住的是一个已修复的缺陷：地形与寻路状态曾经放在模块级全局变量里，
被最后一个 tick 的房间覆写，导致同时进行的两局互相污染建造校验并反复清空寻路缓存。

`map_test.py` 校验地图数据本身。一张地形写错的地图不会报错，只会让对局变成死局：
出生点被山围死、山谷被封、某个出生点跟别人不连通、矿区落在山里采不到 —— 这些
肉眼看不出来，所以逐条断言（含出生点连通性洪水填充与实际开局后的矿区可达性）。

`economy_test.py` 锁住采矿车返程卸矿与随机公共矿区：满载首帧不能改写到精炼厂坐标，
必须驶入卸矿范围才结算；相同地图 seed 复现相同布局，不同对局改变公共矿位置。

`ai_commander_test.py` 只是个壳，转调 `ai_commander/selftest.py`（也可以单独跑）。
它锁住的是 AI 指挥官的克制计算与安全过滤：护甲倍率必须现读 `server.DAMAGE_MULTIPLIER`
而不是抄一份副本，所以改 `catalog.py` 的平衡时这里会跟着报警。

## 图形设置

游戏内菜单可调整：

| 选项 | 说明 |
| --- | --- |
| 画面辉光 | 关闭可省下全部 7 个全屏后处理 pass（含色调映射与 FXAA）；核显机器如果掉帧先关这个 |
| 阴影 | 关闭 / 建筑投影 / 全部投影 |
| 粒子 | 同屏粒子上限 |
| 地图黑幕精度 | 永久探索黑幕的贴图分辨率 |

低配机器建议关闭阴影——单位仍使用贴地圆形阴影，视觉差别不大但便宜得多。
镜头拉远时会自动切换为仍可辨认兵种的低模；单位数量本身不会触发模型硬切换。

## 网络

默认监听 TCP **18081**。局域网联机需要在跑服务器的那台机器上放行该端口
（Windows 防火墙入站规则，或 Linux 的 nftables / ufw）。规则应对本机局域网网段开放，
不要写死某一台机器的 IP。

Windows 示例（管理员 PowerShell，按你的局域网网段改 `-RemoteAddress`）：

```
New-NetFirewallRule -DisplayName "Steel Front LAN RTS" -Direction Inbound -Protocol TCP -LocalPort 18081 -Action Allow
```

如果服务器跑在 WSL2 里，局域网其他电脑通常连不上（WSL2 在自己的虚拟网卡后面，
Windows 的 localhost 转发只对本机生效）。联机请在 Windows 上直接跑 `start-game.bat`，
或在 Linux / macOS 上跑 `./start-game.sh`。
